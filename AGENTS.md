# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## GrokDesk accepted product decisions

- The visual source of truth is `docs/design/grokdesk-light-concept.png`.
- Preserve the three-region task command center: workspace/task navigation, active task timeline, and changes/terminal/context inspector.
- The light theme ships first. Keep shared `light`, `dark`, and `system` theme tokens so dark mode is a theme mapping, not a separate layout.
- Use true white for the main task surface, cool gray for navigation, and a subtle cool tint for the inspector. Blue is the persistent primary/action color; green is success-only.
- The desktop shell is Tauri + React. Use the installed official `grok` binary through `grok agent stdio`; do not reimplement the Grok Build agent or store OAuth tokens in this project.
- Authentication stays with the official CLI through `grok login --oauth`.
- After browser OAuth succeeds, the initiating desktop client must show an explicit success result, restart ACP so it reads the new credentials, and refresh all account information that the official CLI exposes. Do not rely solely on a fire-and-forget desktop event for login completion.
- GrokDesk is single-instance. Opening the desktop shortcut again must focus the existing window so OAuth completion and account state cannot land in a different app process.
- Never fabricate subscription tier or quota values. If the installed official CLI does not expose billing data, show that limitation explicitly and link users to the official SuperGrok management page.
- Windows installation automatically creates a GrokDesk desktop shortcut; shortcut presence is part of release verification.
- The Windows shortcut must use a versioned `.ico` path bundled beside the executable so Explorer cannot reuse stale icon-cache pixels. Release verification must inspect the icon as rendered on the real desktop, not only the source file's alpha channel.
- After every completed GrokDesk version update, also build and overwrite-install that exact version on this workstation. Local delivery is complete only after verifying the installed executable version, desktop shortcut target and versioned icon path, and a successful launch.
- First launch must offer one-click installation of the official Grok Runtime so users do not need to open a terminal first.
- Grok OAuth login and SuperGrok subscription management must remain visible in onboarding and Settings.
- Browser previews must clearly identify simulated install/login data and must never default to a fake signed-in state.
- v0.1.8 establishes the real workspace review loop: users explicitly choose a project folder; Git status and unified diffs come from that folder; accepting stages only the selected file; undoing acceptance unstages it; reverting is always confirmed and never performs an automatic bulk rollback.
- The Changes inspector must state that it includes every Git change in the workspace, including edits that may predate the active Grok task. Development-only simulated changes must be explicitly labeled and must never ship as default product data.
- Plugins and MCP pages must display and mutate only data returned by the installed official Grok CLI. Browser previews remain read-only and never invent extension records.
- Plugin installation and every plugin or MCP removal require explicit user confirmation. Configuration changes must tell users to reconnect ACP before expecting the active Grok session to see them.
- GrokDesk must not request, display, log, or persist MCP tokens and headers. Credentialed servers should rely on official Runtime OAuth or environment-variable references configured outside GrokDesk.
- The task result area scrolls independently. Tools stay docked above the composer, default to the five most recent activities, and offer a working expand/collapse control.
- Agent responses use safe GFM Markdown rendering for headings, lists, links, tables, quotes, inline code, and code blocks; raw HTML remains disabled.
- The composer supports multi-select and drag-and-drop for files and images, with preview, removal, explicit limits, and real ACP capability checks. Attachment contents are turn-scoped and must never be persisted in task history.
- The repository root `README.md` is Simplified Chinese by default. Keep English, Japanese, Korean, and German translations in `README.en.md`, `README.ja.md`, `README.ko.md`, and `README.de.md`, with a language switcher in every file.
- v0.2.0 establishes the local task lifecycle: archived tasks never auto-resume ACP; local task branches copy the visible transcript/context but always start with a fresh ACP session; task JSON import/export is explicit, size/structure validated, bound to the selected workspace on import, and excludes credentials, ACP session IDs, and attachment bodies.
- v0.2.1 establishes the `Ctrl+K` command palette and cross-task search. Search is local to the current workspace, includes active and archived tasks, covers saved titles/messages/attachment names/plans/tool records, and never uploads queries or invents Runtime search results.
- v0.2.2 establishes the local permission and execution audit. Store only redacted permission decisions, Grok tool lifecycles, and workspace-command metadata for the current workspace; keep at most 500 records for 30 days, convert unfinished records to interrupted after restart, require confirmation before clearing, and never persist prompts, responses, terminal output, attachment bodies, OAuth tokens, or MCP headers. Browser previews show no simulated audit records.
- Every README language version starts with the same complete project hero: the real GrokDesk icon, a localized one-line product description, language switcher, truthful live GitHub/release badges, download and section shortcuts, and the actual technology stack. Never add fake community, popularity, ranking, demo, or platform badges.
- Use the public `openai/codex` product and repository as a maturity benchmark for thread lifecycle, permissions and sandbox transparency, background terminals, search, diagnostics, skills, MCP, and keyboard-driven workflows. Preserve GrokDesk's official Grok CLI/ACP boundary: do not copy Codex branding or private behavior, import its auth/protocol, or expose a feature that the installed Grok Runtime cannot support truthfully.
- The Terminal inspector has separate Workspace and ACP log views. Workspace commands run only after explicit user input, are scoped to the selected folder, can stop their process tree, and never persist terminal output in task history. Browser previews remain read-only and never simulate command execution.
- v0.2.3 establishes background workspace execution: up to eight terminal tabs keep independent drafts, history, output, and process state; commands may run concurrently while users switch tasks, pages, or tabs, but any running command still blocks workspace switching. Raw output and parsed test summaries remain session-only. Structured Vitest, Cargo, Jest, and Node counts must come from real output, and browser previews never fabricate terminal or test results.
- v0.2.4 establishes local diagnostics: checks cover the native app, official Runtime, OAuth configuration, ACP connection, workspace/Git, and Runtime-reported MCP state without silently starting a new ACP process. Sanitized support reports exclude absolute paths, account identifiers, prompts, responses, terminal output, attachments, OAuth credentials, and MCP names, endpoints, or headers. Browser previews never fabricate health checks.
- v0.2.5 establishes Runtime context visibility: the Context inspector projects project instructions, Skills, and aggregate Runtime composition from the installed official CLI's `grok inspect --json` result for the selected workspace, then combines prompt capabilities reported by the active ACP session. It offers refresh plus explicit ACP reconnect, never exposes credential values, absolute source paths, or MCP names/endpoints/headers, and shows no simulated context or session identifiers in browser previews. Skills remain read-only unless the official Runtime exposes a dedicated management command.
- v0.2.6 establishes truthful Runtime model profiles: model IDs, descriptions, context windows, and reasoning-effort options come only from the official ACP initialize metadata; the selected profile is passed through the official `--model` and `--reasoning-effort` launch arguments and stored locally with the task. Empty tasks may restart into a fresh ACP session to apply a profile immediately, while tasks with saved conversation never switch sessions silently and only update the default for future tasks. Browser previews never invent a model catalog.
- v0.2.7 establishes background ACP task execution: Runtime process creation, initialize, and session start are serialized because current official `--no-leader` clients can stall when launched simultaneously, while up to four initialized task clients may run concurrently. Only the least-recently-used idle client may be evicted; active turns are never evicted. Users may switch or create tasks while work continues, but workspace switching, task branching/export/archive/delete, OAuth restart, and other destructive lifecycle actions remain blocked for affected running tasks. Background completion, failure, and permission requests must remain task-scoped, visible in the sidebar, actionable through an in-app notification, and accompanied by a Windows taskbar attention request without exposing prompt or response content.
- v0.2.8 establishes macOS as a release platform: support one-click installation through xAI's official `install.sh`, official OAuth/ACP, native traffic-light window chrome, non-interactive workspace shell execution, process-group cancellation, and separate Apple Silicon and Intel DMG artifacts. Unsigned and unnotarized builds must state the Gatekeeper limitation plainly.
- v0.2.9 establishes the trusted release and maintenance loop: check GitHub update metadata automatically, but require separate explicit confirmation for download and install/restart; verify every updater package with the dedicated Tauri signing key; publish a three-platform `latest.json`; smoke-test Windows and macOS package structure; anonymously re-download and checksum public assets; and retain only the two newest public Releases without deleting Git tags. Browser previews never simulate an available update, signature, progress, installation, or restart. Authenticode, Developer ID, and notarization remain truthful optional certificate integrations and must never be claimed when their release secrets are absent.
- v0.3.0 establishes durable task-history storage: installed builds migrate legacy WebView history into a native app-data file, atomically replace the primary file, retain the previous valid version as an automatic backup, and use a close-time browser shadow only for crash recovery. Never silently truncate an over-capacity or malformed store; expose load/save/capacity failures in the task header and Settings. Full-store backup and restore are explicit, validated, limited to 200 tasks and 64 MiB, serialized against pending writes, and remove ACP session IDs, OAuth/MCP credentials, and attachment bodies while retaining potentially sensitive workspace paths. Destructive restore stays blocked while tasks or workspace commands are running.
- v0.3.1 establishes the startup-performance and native-storage smoke-test baseline: keep the task command center and onboarding in the synchronous entry path; lazy-load Settings, Account, Diagnostics, Permissions, Plugins, MCP, and GFM response rendering with stable fallbacks, and preload navigation chunks on pointer or keyboard intent. Review future entry-bundle regressions against the 492.24 KB production baseline. The standalone native smoke test must cover first write, restart reload, previous-version retention, corrupt-primary recovery, save-after-recovery, and double-corruption rejection without real OAuth or paid model calls.
- v0.3.2 establishes the five-language desktop UI: ship complete Simplified Chinese, English, Japanese, Korean, and German catalogs; follow the system by default, fall back to Simplified Chinese for unknown languages, and persist explicit Settings overrides. Localize navigation, controls, forms, dialogs, notifications, accessibility labels, dates, and numbers while preserving Runtime-provided text, model IDs, commands, paths, and raw terminal output verbatim. Keep each catalog in an independent dynamic chunk so localization does not regress the v0.3.1 492.24 KB synchronous-entry baseline.
- Account activity remains split by provenance. Subscription and quota values may come only from the official Runtime billing response. The activity heatmap and recent-task table are local GrokDesk aggregates from saved workspace tasks, messages, and tool records, are labeled local-only, and must never be presented as xAI account usage. Browser previews show no simulated account or activity records.
- The task inspector belongs to the task command center only. Account, Settings, Permissions, Diagnostics, Plugins, and MCP use the full content region and must not be obscured by a stale task inspector, especially at the 980 px minimum window width.


## 提交与推送固定流程

提交前先读 [.github/PREFLIGHT.md](.github/PREFLIGHT.md)，新检出先启用仓库 hooks。精确暂存、检查暂存 diff，运行 `node .github/scripts/preflight.mjs verify --staged`，通过后才提交和推送。检查脚本/工作流引用与漏提交，任何命令失败立即停止；验证记录绑定实际 Git 树，不借用工作目录或旧提交的通过结果。每次一个逻辑改动，其他任务的改动留在原处，必要时隔离工作树验证。发布资格检查仍遵循本项目原有要求。
